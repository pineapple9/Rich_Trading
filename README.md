# Rich Trading

ต้นแบบผู้ช่วย Day Trading สำหรับหุ้นไทย ใช้กับการส่งคำสั่งด้วยตนเองผ่าน **BLS / Streaming / Cash Balance** เริ่มด้วยทุน **2,000 บาท** พัฒนาโดย Python, Streamlit และ SQLite

แอปนี้ทำงานแยกจาก Streaming: **ไม่มีการเชื่อม BLS, ไม่มีข้อมูลราคาสด และไม่ส่งคำสั่งซื้อขาย** หุ้นสหรัฐฯ และการเชื่อมแหล่งข้อมูลที่มีสิทธิ์ใช้งานเป็นงานระยะถัดไป

สำหรับทดลองผ่านเว็บจากมือถือ ใช้ entrypoint `cloud/mobile_demo.py` ซึ่งแยกพอร์ตจำลองต่อเซสชันและไม่เปิดสมุดบันทึกเงินจริง ดู [ขั้นตอน Streamlit Community Cloud](docs/mobile-deployment.md) โค้ดที่เตรียมไว้ยังไม่ใช่เว็บไซต์ที่ Deploy แล้ว

## เริ่มใช้งาน

ต้องมี Python 3.12+ และ [uv](https://docs.astral.sh/uv/)

```bash
cd /workspace/Rich_Trading
uv sync --frozen --extra dev
uv run --frozen streamlit run app.py
```

เมื่อใช้นอก cloud ให้เปลี่ยน working directory เป็นตำแหน่ง checkout ของคุณ แอปฟังเฉพาะ loopback โดยค่าเริ่มต้นและยังไม่มีระบบล็อกอิน จึงควรใช้เป็นแอปส่วนตัว ไม่เปิดสู่เครือข่ายสาธารณะ

```bash
uv run --frozen pytest -q
```

## สิ่งที่ทดลองได้

- **ภาพรวม:** เงินสด มูลค่าพอร์ต กำไร/ขาดทุนที่ปิดแล้วและยังไม่ปิด พร้อมกราฟราคานำเข้า
- **แผนเทรด:** คัดกรองจากมูลค่าซื้อขายประมาณ ดูสัญญาณ ORB ย้อนหลัง และคำนวณจำนวนหุ้นเป็น lot รวมต้นทุนและ slippage
- **พอร์ตจำลอง:** บันทึกซื้อที่ผ่านกฎ อัปเดตราคา ปิดเต็มสถานะ และส่งออกประวัติ CSV
- **บันทึกเงินจริง:** กรอก fill และค่าธรรมเนียมจริงจากรายการยืนยันด้วยตนเอง แยกยอดจากพอร์ตจำลอง และป้องกันเลขอ้างอิงซ้ำ
- **ทดสอบย้อนหลัง:** กลยุทธ์ Opening Range Breakout แบบ long-only ใช้เงินจำลองใหม่แยกจากพอร์ตที่บันทึก
- **ตั้งค่า:** อัตราต้นทุน งบความเสี่ยงต่อครั้ง และเพดานขาดทุนรายวัน บันทึกลง SQLite

## ข้อมูลและการทดลองครั้งแรก

เริ่มจากข้อมูล **สมมติ** ใน `data/sample_intraday.csv`: DEMO1 และ DEMO2 เป็นชื่อสมมติทั้งหมด ไม่ใช่หุ้นที่แนะนำให้ซื้อ มีแท่ง 5 นาทีสองวัน ได้แก่ 6–7 มกราคม 2025

1. เปิดแอปด้วยค่าเริ่มต้น แล้วดู **แผนเทรด** ระบบควรปฏิเสธเมื่อค่าธรรมเนียมสมมติทำให้เกินงบความเสี่ยง
2. ลอง **ทดสอบย้อนหลัง**: ตัวอย่างมี 4 สัญญาณ แต่ค่าเริ่มต้นจะไม่ผ่านกฎเปิดรายการ นี่ไม่ใช่ข้อผิดพลาด
3. หากต้องการทดสอบเส้นทางบันทึกซื้อ/ขาย ให้ตั้งค่าคอมมิชชัน ขั้นต่ำต่อคำสั่ง ค่าธรรมเนียมอื่น และ VAT เป็น 0 **เพื่อจำลองเท่านั้น** จากนั้นสร้างแผนและบันทึกเข้าพอร์ตจำลอง ผลทดสอบแบบไม่มีต้นทุนไม่ควรใช้ตัดสินการเทรดจริง
4. ก่อนใช้ข้อมูลจริง ให้แทนค่าต้นทุนด้วยอัตราและวิธีคิดที่ตรวจสอบจากบัญชีของคุณ

อัปโหลด CSV UTF-8 ได้สูงสุด 5 MB ผ่านหน้าจอ (ตัวอ่านข้อมูลรองรับสูงสุด 10 MiB / 100,000 แถว):

```csv
timestamp,symbol,open,high,low,close,volume,lot_size
2025-01-06T10:00:00+07:00,DEMO1,1.00,1.01,0.99,1.00,1000,100
2025-01-06T10:05:00+07:00,DEMO1,1.00,1.01,0.99,1.00,1200,100
```

- `timestamp` คือ **เวลาเริ่มแท่ง 5 นาที** ต้องมี timezone ทุกแถว เช่น `+07:00` หรือ `Z` โปรแกรมแปลงเป็นเวลาไทยเอง ราคา close จะถือว่ารู้เมื่อผ่านไป 5 นาที
- `volume` คือจำนวนหุ้นที่ซื้อขายในแท่งนั้น; `lot_size` คือจำนวนหุ้นต่อ lot ของหลักทรัพย์นั้นที่ผู้จัดหาข้อมูลยืนยัน ไม่ใช่กฎคงที่ของทั้งตลาด
- ต้องไม่มีแถว `(symbol, timestamp)` ซ้ำ ราคาเป็นบวก OHLC สอดคล้องกัน และ volume ไม่ติดลบ
- มูลค่าซื้อขายในหน้าคัดกรองประมาณจาก `close × volume` ไม่ใช่มูลค่าราย tick และไม่มี bid/ask สำหรับคัดกรอง spread
- พอร์ตจำลองใช้เวลาสิ้นสุดแท่งล่าสุดของชุดข้อมูลเป็นนาฬิกาจำลอง สถานะที่มีราคาเก่าหรือหุ้นที่จะเข้าซื้อมีราคาห่างจากเวลาจำลองเกิน 15 นาทีจะไม่ผ่านแผนใหม่
- ใช้ชุดข้อมูลตามเวลาต่อเนื่อง หากย้อนกลับไปชุดข้อมูลเก่า ยอดประวัติจะแสดงตามเวลานั้น และไม่อนุญาตให้แทรก fill ย้อนก่อนรายการล่าสุด

## ต้นทุนและความเสี่ยง

**ตัวเลขเริ่มต้นเป็นตัวอย่าง ไม่ใช่อัตราทางการของ BLS:** คอมมิชชัน 0.15%, คอมขั้นต่ำ **20 บาทต่อคำสั่ง**, ค่าธรรมเนียมอื่น 0%, VAT 7% ของค่าธรรมเนียมรวม

โมเดลค่าธรรมเนียมต่อขา:

```text
fee = ceil_satang((max(notional × commission_rate, minimum_per_order)
                   + notional × other_rate) × (1 + vat_rate))
```

หากบัญชีของคุณมีขั้นต่ำ **รายวัน**, ยกเว้นบางเงื่อนไข หรือคิด VAT ต่างออกไป โมเดลนี้ยังแทนบัญชีนั้นไม่ได้ ต้องปรับก่อนใช้เงินจริง ช่องยืนยันในหน้าตั้งค่าเป็นการยืนยันของผู้ใช้ ไม่ใช่การรับรองจากโบรกเกอร์

- ทุนเริ่มต้น 2,000 บาท ไม่มีเงินกู้หรือการฝาก–ถอนในเวอร์ชันนี้
- งบความเสี่ยงเริ่มต้น 20 บาทต่อครั้ง / ขาดทุนรายวัน 40 บาท เป็นค่าที่เสนอและแก้ไขได้
- หยุดเปิดรายการใหม่เมื่อขาดทุนรวม 600 บาท (30% ของ **ทุนเริ่มต้น**, ไม่ใช่ยอดสูงสุดของพอร์ต)
- ประเมิน equity รวมสถานะที่ยังไม่ปิด สำรองความเสี่ยงสถานะเปิด และจำกัดงบใหม่ด้วยเพดานรายวัน/รวมที่เหลือ
- คำนวณ adverse slippage 0.10% ทั้งขาซื้อและขาย และค่าธรรมเนียมทั้งสองขา อัตรากำไรสุทธิต่อความเสี่ยงต้องไม่น้อยกว่า 1.5
- ไม่บังคับให้มีรายการ: หาก lot ขั้นต่ำ เงินสด ต้นทุน หรือความเสี่ยงไม่ผ่าน ระบบจะแนะนำให้ข้าม
- Stop เป็นประมาณการความเสี่ยง ไม่รับประกันราคาขายเมื่อเกิด gap หรือสภาพคล่องไม่พอ

**สมุดบันทึกเงินจริงเป็นประวัติ:** อนุญาตให้บันทึกการซื้อขายที่เกิดขึ้นแล้วแม้ฝ่ากฎแนะนำ เพื่อไม่ซ่อนผลขาดทุน แต่ไม่อนุญาตยอดเงินสดติดลบ ต้องบันทึก fill ตามเวลา ไม่มีขายบางส่วน โอนหลักทรัพย์ ฝาก–ถอน การซิงก์บัญชี หรือการตรวจสอบความพร้อมใช้เงินกับ BLS

## กลยุทธ์ทดสอบย้อนหลัง

Opening Range Breakout: กรอบ 10:00–10:15 น. ต้องมีแท่งเปิดครบ ปิดทะลุกรอบสูงพร้อม volume อย่างน้อย 1.5 เท่าของค่าเฉลี่ยในกรอบ แล้วเข้าที่ **open ของแท่งถัดไปที่ต่อเนื่อง** Stop ที่กรอบต่ำและเป้าหมาย 2 เท่าระยะ stop

- สัญญาณมากสุดหนึ่งครั้งต่อหุ้นต่อวัน ถือครั้งละหนึ่งสถานะโดยจัดลำดับตามเวลา (สัญญาณเวลาเดียวกันเรียงชื่อหุ้น)
- ไม่ใช้ high/low/volume ของแท่งอนาคตเพื่อตัดสินสัญญาณ
- หากแท่งเดียวแตะทั้ง stop และ target จะถือว่า stop ก่อน หากเปิดต่ำกว่า stop ใช้ราคาเปิดที่แย่กว่า
- ปิดที่ close ของแท่งสุดท้ายที่มี **ในวันเดียวกัน** หากนำเข้าวันไม่ครบอาจปิดเร็วกว่าตลาดจริง
- เซสชันแบบย่อ 10:00–12:30 และ 14:30–16:30 น. ไม่รองรับวันหยุด ช่วงประมูล การพักซื้อขาย tick size รายหลักทรัพย์ corporate actions หรือ execution queue
- ไม่ใช่การยืนยันกำไร ต้องเลือกข้อมูลที่มีสิทธิ์ใช้งานและคุณภาพเพียงพอ แยกช่วงพัฒนา/ประเมิน และทดสอบเดินหน้าก่อนใช้เงินจริง

## การเก็บข้อมูล

ฐานข้อมูลเริ่มต้น `var/trading.sqlite3` ถูก Git ignore เก็บพอร์ตจำลอง ประวัติเงินจริง ราคาประเมิน และการตั้งค่าไว้แยก ledger ใช้ Decimal สำหรับการคำนวณเงิน การบันทึกซื้อจำลองตรวจงบและเขียนรายการใน transaction เดียว

เปลี่ยนตำแหน่งฐานข้อมูลได้ด้วยตัวแปร `RICH_TRADING_DB` ไม่ต้องใช้ secret หรือข้อมูลล็อกอินโบรกเกอร์:

```bash
RICH_TRADING_DB=/path/to/private/trading.sqlite3 uv run --frozen streamlit run app.py
```

สำรองฐานข้อมูลส่วนตัวก่อนย้ายเครื่องหรือเปลี่ยนข้อมูล ห้าม commit ฐานข้อมูลหรือข้อมูลบัญชีจริง แอปนี้ออกแบบสำหรับผู้ใช้คนเดียวในเครื่องส่วนตัว
